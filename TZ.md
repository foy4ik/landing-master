# ТЗ: Лендинг мастера или эксперта (landing-master)

Одностраничный адаптивный сайт для частного специалиста: мастера маникюра, фотографа, репетитора, психолога, тренера. Заявки с формы приходят в Telegram. Покупатель часто не разработчик, поэтому главное — чтобы сайт можно было править в любом редакторе и залить на любой хостинг.

## Технологии

Исключение из общего стека: чистые HTML, CSS и JavaScript без фреймворков, сборки и Docker. Шрифты лежат в проекте, внешних зависимостей нет. Все места, которые покупатель меняет, помечены в HTML комментариями «<!-- РЕДАКТИРОВАТЬ: ... -->», цвета и шрифты — переменные в начале CSS.

## Секции

1. Первый экран: имя, специализация, оффер в одну строку, фото, кнопки «Записаться» и «Написать в Telegram».
2. Услуги и цены: карточки с названием, описанием, длительностью и ценой.
3. Обо мне: текст, опыт цифрами, сертификаты.
4. Работы: галерея с просмотром на весь экран и свайпом.
5. Отзывы: карточки или скриншоты переписок.
6. Как проходит работа: 3–4 шага.
7. FAQ на нативных details.
8. Контакты: адрес, карта Яндекса (вставка конструктора, загружается при прокрутке), телефон, мессенджеры, форма заявки.

Любую секцию можно удалить, и вёрстка не сломается. Меню строится по секциям автоматически.

## Форма заявки

- Поля: имя, телефон с маской, услуга из списка, комментарий, чекбокс согласия на обработку персональных данных со ссылкой на политику. Без согласия форма не отправляется.
- Токен бота нельзя держать в браузере, поэтому форма отправляется на маленький серверный обработчик. В комплекте два варианта: send.php для обычного хостинга с PHP (токен в отдельном config.php) и скрипт для Cloudflare Workers для статического хостинга. Адрес обработчика задаётся в одной строке JS.
- Защита от спама: скрытое поле-ловушка, минимальное время заполнения, ограничение частоты в обработчике. Данные формы экранируются перед отправкой в Telegram.
- Понятные состояния: отправка, успех, ошибка с предложением написать напрямую.

## Остальное

- Три готовые цветовые палитры (например, нежная, строгая и яркая) переключаются одним атрибутом на html.
- SEO: title, description, Open Graph, разметка Schema.org LocalBusiness или Person, favicon.
- Шаблон страницы policy.html с политикой обработки персональных данных и полями для заполнения. В README — предупреждение, что текст нужно дополнить под себя.
- Необязательно: счётчик Яндекс Метрики, включается номером в одной строке.
- Инструкции в README: как заменить тексты и фото, как выложить на российский хостинг с PHP, на GitHub Pages с Cloudflare Worker, как привязать домен.

## Демо

Лендинг выдуманного мастера маникюра на GitHub Pages. Форма в демо не отправляет данные, а показывает, как выглядела бы заявка в Telegram. Переключатель трёх палитр виден только в демо. Фото — со свободной лицензией, источники в REPORT.md.

## Готово, когда

- [ ] Lighthouse на мобильном не ниже 90 по всем четырём показателям.
- [ ] Нет горизонтальной прокрутки на 375, 768 и 1280 px, проверено скриншотами.
- [ ] Оба обработчика формы проверены локально (PHP в Docker для теста, Worker через wrangler dev или юнит-тестами) с фейковым Telegram API.
- [ ] Удаление любой секции не ломает страницу и меню.
- [ ] Всё из общих требований, применимое к статическому сайту, выполнено.

## Общие требования ко всем моим шаблонам

Этот раздел одинаков для всех моих шаблонов. Если он расходится с разделами выше, приоритет у разделов выше — они про конкретный шаблон.

Шаблон продаётся двумя способами: исходники для самостоятельного запуска (покупатель часто не программист) и установка под ключ мной. Поэтому главное требование — покупатель запускает шаблон за вечер по README и настраивает его под свой бизнес без правки кода.

### Стек

| Тип шаблона | Стек |
| --- | --- |
| Telegram-боты | Python 3.12, aiogram 3, SQLite через aiosqlite, pydantic-settings, APScheduler для задач по времени |
| Mini App | Фронтенд: React + TypeScript + Vite, Telegram WebApp SDK. Бэкенд: FastAPI + SQLite. Бот на aiogram для кнопки меню и уведомлений |
| Сайты | Указано в разделе шаблона |
| Запуск | Docker + Docker Compose, одна команда docker compose up -d |

### Архитектура ботов

- Бизнес-логика (services) отделена от Telegram: хендлеры только принимают ввод и вызывают сервисы. Так позже можно добавить адаптеры для MAX и VK без переписывания логики. Сами адаптеры сейчас не делаем.
- Диалоги на FSM aiogram, с кнопками «Назад» и «Отмена» на каждом шаге.
- Права администратора — по списку ADMIN_IDS из .env.
- Middleware против флуда: не больше нескольких действий в секунду от одного пользователя.
- Любая ошибка логируется, пользователь видит понятное сообщение, а не тишину.

### Архитектура Mini App

- Каждый запрос к бэкенду проверяет initData Telegram по HMAC с токеном бота. Без валидной подписи — 401. Проверка покрыта тестами.
- Интерфейс подстраивается под тему Telegram (themeParams), использует MainButton, BackButton и тактильный отклик.
- Вне Telegram (обычный браузер) показывается экран «Откройте в Telegram» со ссылкой на бота. В режиме разработки работает мок Telegram-окружения.
- Фронтенд и бэкенд отдаются через Caddy с автоматическим HTTPS: Mini App работает только по HTTPS.

### Настройки покупателя

- **.env** — только секреты и технические параметры: токены, ADMIN_IDS, часовой пояс, адреса. В репозитории лежит .env.example с комментарием к каждой строке.
- **config/texts.yaml** — все тексты, которые видит пользователь: приветствие, кнопки, уведомления. Покупатель меняет их без кода.
- **config/settings.yaml** — бизнес-настройки: название, контакты, рабочие часы и прочее, указанное в разделе шаблона.
- Данные, которые меняются часто (услуги, товары, тарифы), редактируются в админке бота или Mini App, а не в файлах.

### Демо-режим

Каждый шаблон запускается в демо-режиме флагом DEMO_MODE=true. Демо нужно для кнопки «Попробовать демо» на витрине.

- При старте база заполняется реалистичными примерами данных под нишу шаблона. Все имена и данные выдуманные.
- Любой пользователь может переключиться в роль администратора кнопкой «Посмотреть админку» и вернуться обратно. Так посетитель видит обе стороны продукта.
- Сверху или в приветствии понятная пометка: «Это демо-версия шаблона», со ссылкой на витрину.
- Данные сбрасываются к исходным раз в сутки ночью.
- Действия, которые затрагивают реальных людей (рассылки по всей базе, исключения из канала), в демо показываются, но выполняются только для самого посетителя.

### Качество и проверка

- Тесты pytest (для фронтенда — vitest) на всю бизнес-логику: расчёты, статусы, проверки, расписания. Живые запросы к Telegram в тестах не используются.
- ruff без замечаний, аннотации типов, понятные имена, комментарии там, где логика неочевидна.
- Перед завершением убедиться, что: тесты зелёные, docker compose build проходит, приложение стартует без ошибок (при отсутствии токена — понятное сообщение, а не трейсбек), фронтенд собирается. Для Mini App и сайтов — скриншоты Playwright на 375 и 1280 px в светлой и тёмной теме, которые нужно самому просмотреть и исправить найденное.
- Секреты никогда не попадают в git: .env, базы и сессии в .gitignore с первого коммита.

### Комплект для покупателя

- **README.md** на русском, для человека без опыта: что умеет шаблон, как получить токен у BotFather, как арендовать VPS и поставить Docker, как запустить, как настроить тексты, как обновить. Каждый шаг — конкретные команды.
- **docs/ADMIN.md** — инструкция для владельца бизнеса: как пользоваться админкой.
- **LICENSE.md** — заготовка: использование покупателем в своих проектах и проектах клиентов, перепродажа исходников запрещена. С пометкой, что текст я проверю сам.
- **CHANGELOG.md** с версией 1.0.0.
- **scripts/package.sh** — собирает dist/<slug>-v<версия>.zip для продажи: без .git, тестов разработки, TZ.md, PROMPT.md, docs/plan.md, docs/decisions.md, docs/REPORT.md, .env и баз.

### Где будут жить демо

Демо живут на одном VPS: каждый шаблон — отдельный docker compose-проект со своей базой. Боты работают через long polling и домена не требуют. Mini App нужен HTTPS, поэтому для них будет домен с поддоменами. Лендинг и портфолио публикуются на GitHub Pages как статика.
