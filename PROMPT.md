В этой папке лежит TZ.md — полное техническое задание на шаблон «Лендинг мастера или эксперта» (landing-master). Шаблон — это товар: я продаю его исходниками и ставлю клиентам под ключ. Раздел «Общие требования» в конце TZ.md одинаков для всех моих шаблонов.

Сделай шаблон полностью за один заход, без остановок на вопросы и подтверждения:

1. Прочитай TZ.md целиком. До кода запиши план в docs/plan.md с чекбоксами и иди по нему, отмечая выполненное.
2. Спорные места решай сам разумным вариантом и записывай в docs/decisions.md: вопрос, решение, почему. Не останавливайся, чтобы спросить меня.
3. Если раздел шаблона расходится с общими требованиями, приоритет у раздела шаблона.
4. Библиотеки и API сверяй с документацией актуальных версий, а не по памяти.
5. Сразу сделай git init и коммить логическими шагами, сообщения на английском. Ничего не пушь и не создавай на GitHub.
6. Не завершай процессы по имени (taskkill /IM, pkill, killall), только свои по PID. Не трогай файлы вне этой папки.

Особое внимание в этом шаблоне:
- Стек — исключение: чистые HTML, CSS и JS без сборки и фреймворков. Покупатель должен править сайт в обычном редакторе.
- Токен бота никогда не попадает во фронтенд. Два обработчика формы — send.php и Cloudflare Worker, оба проверены с фейковым Telegram API.
- Скриншоты 375/768/1280 и Lighthouse на мобильном не ниже 90 по всем показателям — проверь сам и исправь найденное.
- Docker нужен только для локальной проверки PHP-обработчика, в комплект покупателя он не обязателен.

Работа закончена, только когда выполнены все пункты «Готово, когда» и все проверки из раздела «Качество и проверка», применимые к этому шаблону. Если что-то не проходит — исправляй, а не описывай.

В конце напиши docs/REPORT.md по требованиям из TZ.md и короткое сообщение мне: что готово, какие мои данные нужны для запуска демо, где отклонился от ТЗ.
